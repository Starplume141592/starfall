# 星陨 · 更新计划

> 来源：玩家试玩反馈 20 条 + 工程侧实测发现的问题，合并去重后按「影响 × 成本 × 是否阻塞后续」排批。
> 规则：**每一批做完都必须能跑、能验证**；不换引擎、不加依赖、不加外部资源文件。

---

## 0. 排批原则

| 判据 | 说明 |
|---|---|
| 先便宜的 | 能当天改完、能立刻体感到的排最前（改数值/CSS/一行逻辑） |
| 再伤人的 | 影响"这一局白玩"的问题优先于"不够好玩"的问题 |
| 阻塞优先 | 挡住其他改动的问题先修（例如层序错误会影响后续所有弹幕设计） |
| 新系统单独拉 | 商店 / 存档 / 战机这三条互相耦合且改变类型定位，必须单独一轮并先定方向 |

**不做的事**：换引擎（实测 420 敌人 p50 5.7ms，canvas 2D 还有 3 倍余量）、引入打包器、引入外部美术资源、改玩法核心循环（幸存者三选一）。

## 第一批 · P0 零风险（当天可见）

| # | 项 | 目标 | 改法 | 验收 |
|---|---|---|---|---|
| 1 | **顶部正中计时 + 倒计时** | 玩家全程要瞥的信息不该塞在左上角遥测行里 | 新增 `#clock`（大号计时 + 其下倒计时）；从 `#stats` 移除「时间 / 下波」 | ✅ **已完成**：中心 418 / 画布中心 419，40px，无重叠，0 error |
| 2 | **受击震动减弱** | 玩家反馈"伤害反馈过强，可考虑取消" | 受击 12 → **4**；击杀 3~5（随连击增长）→ **固定 2**；Boss 保持 20 | ✅ 已改；代码层可查（未做主观体感验证，等玩家反馈） |
| 3 | **无敌闪烁降频** | 原 `floor(invuln*20)%2` = 每秒 20 次硬翻转，落在光敏峰值频段 16–25Hz | 改成 **5Hz 呼吸式**透明度脉动（0.55~1.0） | ✅ 实测峰谷差 15.5 亮度、平滑振荡，无硬翻转 |
| 4 | **闪光票据制** | 各处直接赋值 `flashA`，密集击杀一秒能闪七八次（WCAG 2.3.1 要求 ≤3 次/秒） | 新增 `flash()`：每 340ms 一张票据，冷却期内**直接丢弃**（不打折补发） | ✅ 实测 **0.6 次/秒**（阈值 3）；玩家主动放的战术弹与结算闪不占票据 |
| 5 | **弹幕层序 + 火花配色** | 敌方弹幕画在粒子之前，粒子处于加法混合 | 把敌方弹幕移到粒子之后（顺序：粒子 → 敌方弹幕 → 玩家）；同时把爆炸火花的暖黄高光改成冷白蓝 | ✅ 已完成，但**原假设被证伪**：加法混合的粒子并不会遮住弹幕 —— 弹幕核心在有无粒子时都是饱和白，5×5 峰值采样区分不出来。层序改动的实际收益是"轮廓不被覆盖"（零成本的原则性修正）。**真正的问题是色相撞车**：30% 火花用暖黄 `#ffe066`，与危险琥珀同色系，一秒几百颗会被读成弹幕 —— 这才是有实效的那半 |

**顺带完成（原属第二批第 6 项）**：XP 曲线前期抬高
`expNeed: 4 + lv*3.2 + lv²*0.55` → **`9 + lv*5.2 + lv²*0.6`**
理由：第一分钟杀 173 只 = 346 经验，而旧曲线 1→10 级只要 318 → **第一分钟连升 10 级**，武器 5 分钟全满级，后面 8 分钟构筑定型。

| 指标 | 改前 | 改后 |
|---|---|---|
| 第一分钟升级次数 | 9–10 | **7–9** |
| 3 分钟等级 | 18–26 | 14–23 |
| 5 分钟等级 | 35–38 | 28–35 |
| 终局等级 | 66–70 | **61–63** |
| **武器全满级时间** | ~5.0 分钟 | **5.8 分钟（中位 350s）** |
| 单局时长（6 局） | 中位 13.3 | **12.8 / 13.1 / 13.1 / 13.3 / 13.3 / 13.3，中位 13.3** |
| 早死 | 11 局里 2 局 | **6 局 0 局** |
| 帧时间（420 敌人 + 120 弹幕） | p50 5.7 | **p50 4.3 / p90 5.3** |

> 注："武器全满级"只从 5.0 推到 5.8 分钟 —— 一局 13 分钟里仍有 7 分钟构筑已定型。要把它推到 8 分钟以上，得动**武器等级上限（5 → 7）**并同步削伤害，那是第二批的事。

### 补充修复：关闭全图自动拾取（测试期开关）后暴露的三个问题

`ORB_AUTO_PICKUP` 之前是 true（测试用），关掉它之后残片经济立刻崩了 —— 三个原因，全部已修：

1. **掉落数量**：原来每只怪最多掉 **8 颗**残片。开着全图拾取时这只是"碎片雨"的好看；关掉后战场几秒内就顶到 220 上限，而玩家物理上不可能走完 → 经验被稀释。现改为**一怪一颗**（精英/首领 4 颗），经验总量不变。
2. **上限处理**：超限时原来**直接删掉最远的残片** = 静默销毁经验（表现是"等级涨得莫名慢"，玩家查不出原因）。现改为把价值**并入**最后一颗，并把残片视觉尺寸随价值缓慢放大（上限 1.9×），让"大残片"看得见。
3. **模拟机器人**：原来的机器人只风筝、从不捡碎片（12 方向势场里没有残片项），关掉全图拾取后它把残片全丢在身后 → 测出来的是"机器人不会玩"，不是游戏问题。现在给势场加了**顺路捡碎片**项（视线 700px，加分封顶 2.2，保证"不为了捡碎片往敌群里钻"）。

实测（每局 1/60 固定步长自动对战）：7 局全部跑到 15 分钟满、等级 67–70、波次 44–45，0 局早死；残片场上余量 47–100（不再堆死）。
注意口径：本批机器人**移动策略同时改了**，因此与"关掉拾取前"的批次不能严格对比（那批是另一个走位策略跑出来的）。

## 第四批 · P3 结构性新系统（单独一轮，先决策）

| # | 项 | 为什么要单独一轮 |
|---|---|---|
| 16 | **商店系统** | 需要货币来源 → 与"存档"耦合 |
| 17 | **存档 / 元进度** | 目前只存一个最高纪录（localStorage 单键）。加了元进度 = 游戏从"单局 roguelite"变成"有跨局成长的 roguelite" |
| 18 | **战机选择** | 需要机体差异化设计 + 解锁条件 → 依赖存档 |

**决策点只有一个：要不要跨局元进度。** 要 → 三条一起设计；不要 → 跳过整批。
