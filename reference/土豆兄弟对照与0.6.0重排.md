# 《星陨》0.6.0 重排稿 —— 土豆兄弟对照与新的落地顺序

> **这份是什么**：把三份 Brotato 拆解（`土豆兄弟拆解.md` wiki/公告 · `土豆兄弟拆解-压力与失败.md` 机制对照 · `土豆兄弟拆解-游戏内数据实测.md` 游戏文件与存档）**压成对《星陨》的裁决**：哪些已定要保留、哪些要改、哪些要推倒，以及**新的落地顺序与判据**。
> **与其它文档的分工**：`设计稿-局内重构.md` 记"要去哪"（本文件**修订它**）；`DECISIONS.md` 记"为什么这么定"（本文件里未被用户裁决的部分**还没进 DECISIONS**）；`STATUS.md` 记做到哪了。
> **最后更新**：2026-09-29 ｜ **状态：待用户逐条裁决（§5 有 6 条）**

---

## 0. 一句话结论

**我们把判据押错了地方。** Brotato 把"每波都在做取舍"的决策密度放在**波与波之间的经济**（一局 **20 次商店 × 4 格** + **约 20 次升级 4 选 1**，每个决策都拖着一条"不可逆或折价"的尾巴），而**局内事件在它的三年半历史里根本不存在** —— 1.1.15（2026-05）才给最高难度加了两个"**改写场地**"的坏天气，无目标、无奖励、无选择。

所以：

1. **原「阶段 0 的判据」作废** —— 它让一个人去打一个按设计就不可能产生差别的版本（阶段 0 明确不做任何产生压力的机制），这个顺序错误由我承担。
2. **商店经济提到第一位**（原阶段 1 → 新阶段 A），**武器即构筑**排第二（原阶段 2 → B），事件降级为**可选的加压层**（原阶段 4 的核心 → 新阶段 D，且只有 A–C 跑通才做）。
3. **判据全部换成可自动测的结构指标**（§4 每阶段都给了），人的"好不好玩"只做**终审**，不再当唯一门禁。

## 1. 双方事实基线（一页速查）

## 2. 逐条对照 · 我们「已定」的 11 条（`设计稿 §一`）

| 条目 | Brotato 的做法 | 裁决 | 理由 |
|---|---|---|---|
| **A1** 武器只留品级，砍 1–7 级 | 每档是**独立资源条目**（203 件），**没有统一倍率**，逐武器手调 | ✅ **保留，但修实现方式** | 我们只有 11 把武器 → 11 × 4 档 = 44 条数据，**手调完全可行**，比乘数表更好调 |
| **A2** 合成给「品级」（乘数层） | 同名同档 → 合成，最高 T4，吃 2 吐 1，**占格减一** | ✅ 保留 | 与 Brotato 同构；我们写下的"占格 2→1 顺手解决满格"也对 |
| **A3** **事件驱动（主骨架）** | **没有这个东西**（见 §0）；它的 event 是加压不是骨架 | ❌ **推翻作为主骨架**，降级为阶段 D 的**可选加压层** | 三年半、几百万玩家的样本里没有先例，我们不能拿它当骨架、也不能拿它当"Brotato 也这么做"的背书 |
| **A4** 升级不再给武器强化 | 升级**只给属性卡**（20 属性 × 4 档 × 4 选 1） | ✅ 保留并**加宽池子** | 方向完全正确；但池子必须有 **≥20 项**才能独自承担不确定性 |
| **A5** 商店肉鸽化 | 分类池 + 刷新 + 锁定 + 价格随波 + 折扣 + 回收 + 禁购 | ✅ **保留，并提到第一位** | 这才是它的决策引擎 |
| **A6** 波次≈1 分钟，几波成段 | 无"段"概念，纯 20 波 | ✅ 保留 | 我们的段结构本身没问题 |
| **A7** 事件成功/失败与奖励挂钩 | **没有对应物**（Brotato 连"波级失败"都没有） | ⚠️ **修订** | "少拿 20%" 是**无痛惩罚**：Brotato 的尺子是"这条负面会不会让玩家**不能做某件事**"。惩罚要落在**可选集**上 |
| **A8** 一局 = 3 段 ×（3 波 + 1 事件），12–15 分钟 | 17.5 分钟 / 20 波 | ✅ 保留（实现里已是 4 波/小节，13.5 分钟） | 时长不是问题所在 |
| **A9** 小铺 / 大铺分开 | **没有大小铺**，但每次 4 格、**锁定免费** | ⚠️ **保留但改判据** | 大小铺的差别应该落在**商品类别**（应急/锻件/质变件/服务），而不是件数 3 vs 6 |
| **A10** 每波之间都能进店（12 次） | **20 次/局** | ✅ 保留（我们更少，不必再减） | 12 次不嫌多这条已被 Brotato 证明 |
| **A11** 武器来源必须可扩展（单入口） | 武器只从商店来，道具还能从箱子掉 | ✅ 保留 | `grantWeapon(id, source)` 的单入口设计是对的 |

## 3. 逐条对照 · 我们「待定」的 12 条（`设计稿 §四`）

|---|---|---|---|

## 4. 重排后的落地顺序（**A → E**）

> 原则：**先做"决策密度"，再做"变数"；事件最后做，且允许直接砍掉。**

### 阶段 A：把"波与波之间"变成决策层 ⭐ **第一位**

| 做什么 | 细节（可以照抄的形状） |
|---|---|
| 分类商品池 | 应急 / 锻件 / 质变件 / 服务 四类（`设计稿 §3.1` 原本就有） |
| **价格随波数上涨** | 抄形状：`floor((base + 小节号 + base × 0.1 × 小节号) × 折扣)`。**平价加项**会让便宜货后期更不划算 —— 这是"后期必须挑"的结构性来源 |
| **免费刷新 1 次 + 付费刷新** | 付费刷新价：**随波数猛涨**（Brotato 是商品价 ×3 而刷新价 ×23–30），店内每次递增，**每次进店重置** |
| **锁定** | **免费**、跨波保留、**冻结价格** |
| **收入结构重做**（解掉最大空白） | 碎片 **一份两用**（经验 + 信用点）；掉率随小节轻微衰减；**不做利息** |
| 卖同名武器 / 拆解服务 | 保留（`设计稿 §3.2`）—— 它们是把"6 格上限"变成**花钱的决策**的关键 |

**判据（可自动测，用现成的 `__game.sim()`）**：

1. 跑 **20 局**，统计"进店时有几次**买不起自己想买的第二件**" —— 目标：**≥ 40% 的进店**存在真实取舍；
2. 一局**购买次数中位数 ≥ 8**（现状 ≈ 4）；
3. 一局内**刷新被使用**的局占比 ≥ 50%，且**平均刷新次数 1–3 次**（太少=没用，太多=无脑）。

**人的终审**：只回答一句 —— 「**有没有哪一次，你因为钱不够而放弃了你想要的东西？**」

### 阶段 B：武器即构筑（6 槽 + 合成 + 类别 + 属性缩放）

| 做什么 | 细节 |
|---|---|
| **6 格武器槽 + 同名可重复** | Brotato 存档亲证：6 把、`weapon_hand` ×2 |
| 同名同品级合成 | 保留 A2；合成后占格 2→1 |
| **武器类别阈值**（替代"套装"） | ⚠️ **重要风险**：Brotato 能玩套装是因为它有 **78 把武器 × 17 类**；我们只有 **11 把** → 直接抄"套装阈值 2/3/4/5/6"会**凑不出来**。**先做粗类别（3–4 类，阈值 2 / 4），等武器扩到 20+ 再细分** |
| **武器吃不同属性**（`scaling_stats`） | 这条**已经在 `DECISIONS.md` 待确认表最后一行躺着**，被排在阶段 0–5 之后。它是"属性投资改变哪把武器值得留"的唯一机制 → **提到 B** |

**判据**：一局内**合成发生 ≥ 2 次**；6 格**满格时间点**出现在第 2 段之后；**武器类别阈值达成率**在 30–70%（太低=没意义，太高=白送）；属性选择与武器类别的**相关性**可观测（玩家在同类武器里做出取舍）。

### 阶段 C：变数（可购买的压力 + 机体硬限制 + 预告）

| 做什么 | 细节 |
|---|---|
| **把"更难但多拿"做成货架商品** | Brotato 一整类：`Bait`（下一波开头多刷 7–8 只特殊敌人，杀了给材料）/ `Celery Tea`（下一波敌人血 +100% 换 +50% XP）/ `Peacock` / `Scarf` / `% Enemies`。**变数因此是玩家挑的、代价提前写明、收益自己预算** —— 比"系统发事件"强得多，且**不需要新敌人、不需要新目标判定** |
| 机体改成**硬限制** | 不是"数值不同"，而是"这一局**不能做某件事**"（禁用某类武器 / 禁用某个升级项 / 用血量买武器） |
| **事件提前预告** | 下一段的事件类型、条件、失败代价，**在上一段的大铺里就能看到** —— 让"为它改构筑"成为当下的决策 |

**判据**：一局里"更难但多拿"类商品的**购买率**；不同机体之间的开局武器/属性分布**显著不同**。

### 阶段 D：事件的牙齿（**只有 A–C 跑通才做**）

照 Brotato 的最低可行形态做（`拆解-压力与失败 §7 对照 8`）：

| 要素 | 做法 |
|---|---|
| 是否当压力来源 | **否** —— 它的作用是**加压**，不是奖励 |
| **必须改写场地** | 护航 + **你的 AoE 会伤到运输舰**（`设计稿 §4.3 #12` 原本就写了这条，且被它自己标为"最关键的一条"）；或弹幕扫场、迷雾式信息限制 |
| 必须提前可见 | 进段前可见（见阶段 C） |
| 失败惩罚 | 落在**可选集**（少一格 / 时限更短 / 锁一个升级项） |
| 开关 | 提供"关掉事件"的选项，便于隔离变量做对比验证 |

**判据（"火力成为负担"的可测定义）**：护航事件里，**AoE 型构筑的失败率比单体构筑高 ≥ 20 个百分点**。达不到，就说明事件仍然没牙齿，**直接砍掉事件**而不是继续调数值。

### 阶段 E：结算 / 存档 / 局外

原阶段 5，不变。

## 5. 需要你裁决的 6 条（**这是本文件的全部要点**）

| # | 问题 | 我的推荐 |
|---|---|---|
| 1 | **A3「事件驱动」是否降级**（不再当主骨架，改为阶段 D 的可选加压层） | ✅ **降级**。理由：Brotato 三年半无先例；且我们的实测已证明"有目标 + 奖励档位"不产生决策 |
| 2 | **收入结构**：碎片**一份两用**（经验 + 信用点）还是保持分离 | ✅ **一份两用**。理由：这样"攒钱 vs 升级"的内耗消失，取舍全集中到商店；也顺手解决了阶段 1 卡住的"信用点收入结构未定" |
| 3 | **品级数值**：统一乘数 vs **逐档手调** | ✅ **逐档手调**（11 武器 × 4 档 = 44 条）。理由：Brotato 也是逐条手调；我们的统一乘数已自证是陷阱选项 |
| 4 | **武器类别阈值**要不要做 | ⚠️ **做，但先做 3–4 个粗类、阈值 2/4**。理由：我们只有 11 把武器，直接抄 15 类 × 2/3/4/5/6 会凑不出来 |
| 5 | **原阶段 0 的判据是否作废**，换成 §4 的可测指标 | ✅ **作废**。理由：它把只有人能判的问题交给了一个按设计不可能产生差别的版本 |
| 6 | **事件保留与否** | ✅ **保留但推迟到 A–C 之后**；若你想更快看到"决策密度"，**阶段 D 可以直接跳过**，等 A–C 的判据达标再回头做 |

## 6. 明确**不抄**的东西

| 不抄 | 为什么 |
|---|---|
| 20 波 / 17.5 分钟 | 我们 13.5 分钟，时长不是问题 |

| 8 个禁购 token（1.1.13+） | 那是接手团队（Evil Empire）加的东西，且依赖大池子；后置 |

## 7. 存疑与风险（**动手前必须知道**）

| # | 风险 | 说明 |
|---|---|---|
| 1 | **刷新价的确切系数**没有任何一手来源（Brotato 官方只说过"更便宜了""略涨"两句），三种社区说法在 W20 分别给出 23 / 16 / 30 | 我们**抄形状、不抄系数**：只要保证"刷新价涨幅远大于商品价涨幅"即可 |
| 2 | **一局材料总收入**无一手来源（Brotato 那边也没有），我们的 `355` 是自测值 | 阶段 A 必须用 `sim()` 跑出我们自己的收入曲线，再定价格 |
| 3 | **11 把武器撑不起套装/类别阈值** | 这是阶段 B 最大的结构性风险，见 §5 #4 |
| 4 | 12 次进店 < 20 次 | 经济压力的密度可能不够；若判据达标率低，**优先加进店频率而不是加钱** |
