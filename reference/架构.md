# 星陨 · 当前框架

> 一句话：**原生 ES module + canvas 2D，没有打包器、没有依赖、没有美术资源**。
> 四个 JS/CSS 文件各管一段，改动范围永远锁定在一个文件内。

## 1. 怎么跑

```bash
npm run dev          # → http://localhost:5173/   （scripts/serve.mjs，20 行 node 静态服务器）
```

**必须走服务器**：代码是原生 ES module，`file://` 会被浏览器 CORS 拦掉。
不再需要 Vite（原来那套已废弃），也不需要任何构建步骤。

窗口失焦时 Chrome 会把 rAF 限到 ~1fps，游戏时钟几乎不走 —— 调试验证前先把浏览器切到前台。

## 2. 文件与职责

| 文件 | 管什么 | 改动时机 |
|---|---|---|
| `index.html` | DOM 骨架：`#stage` / `#hud` / `#overlay` / `#hint`，引入 `theme.css` 与 `src/game.js` | 只在加/改 DOM 元素时动；**必须同步 theme.css 与 game.js** |
| `src/config.js` | 纯数据 + 纯函数：`VIEW`、`WEAPONS`、`STATS`、`MODULES`、`ENEMY_TYPES`、`BOSS_TYPES`、`SHIPS`、`SHOP_ITEMS`、`META_UPGRADES`、半径常量、曲线（`expNeed` / `SPAWN.rate`）、`mkName`kName` | **调数值只改这里** |
| `src/game.js` | 状态、输入、刷怪、Boss 状态机、武器、拾取、装备终端、主循环、HUD 刷新 | 逻辑改动 |
| `src/render.js` | 全部绘制：背景/网格/冲击波/弹体/单位（几何组合）/玩家/飘字/小地图，含发光贴图缓存与视觉收缩系数 | 画面改动 |
| `src/audio.js` | 程序化音效（WebAudio 实时合成，零音频资源）：射击/命中/击杀/拾取/升级/跃迁/Boss/受伤/结算，内置每 60ms 声音预算防噪 | 音效改动 |
| `src/theme.css` | 全部样式：舞台、HUD、装备终端/超频跃迁面板、暂停、结算、底部提示 | 只写 CSS，不碰 JS |

`reference/archive-phaser/` 是早期 Phaser 版本的存档，与当前项目无关，不要引用。

## 3. 数据流

```
config.js ──常量/曲线──▶ game.js
                        │
       每帧 loop(now)   │
       ├─ hitStop 时间缩放 → dt
       ├─ update(dt)    │  改 player / G（移动、武器、敌人、拾取、波次）
       ├─ render(ctx, { W, H, G, player, shake, flashA, flashColor }) ──▶ render.js 画到底层 canvas
       └─ updateHUD()   │  写 DOM：#hpFill / #hpHp / #xpFill / #xpVal / #sLv / #sWave / #sCredit / #sZoom / #sKill / #clockTime / #clockNext / #loadout / #combo

输入：window keydown/keyup → keys{}；canvas 触摸 → player.touch（坐标经 toLocal 换算）
装备终端：gainExp → showUpgrade()（写 #panel innerHTML + G.paused=true）→ 点击或按 1/2/3 → chooseOption → 恢复
```

## 4. 坐标、镜头与缩放

三层尺度，别混：

| 层 | 常量 | 说明 |
|---|---|---|
| 世界（地图） | `WORLD = 2560×2560` | 玩家真正活动的范围，有硬边界；`render()` 里画了边框 |
| 视口（镜头） | `VIEW = 1280×720` | 一屏能看到多大；**逻辑**尺寸恒定，不随窗口变 |
| 舞台（DOM） | `#stage` 的 CSS 尺寸 | 窗口尺寸 × `scale = min(窗口宽/1280, 窗口高/720)`，等比居中留黑边 |
| 镜头高度 | `VIEW_ZOOM = {min:0.7, max:1.6, step:0.1}` | 玩家可调；zoom<1 = 镜头拉高看得更远，>1 = 推近。存 localStorage |

- 相机：`G.cam` 是视口左上角的世界坐标，每帧 `updateCamera()` 让玩家居中并夹在 `[0, WORLD-视口]` 内
- **视口尺寸会随 zoom 变**：`viewW() = W/zoom`、`viewH() = H/zoom`。相机夹取、刷怪圈、剔除范围、小地图视野框全都必须用它，**不能用裸的 `W/H`**（否则拉高镜头时怪会刷在画面里）
- 镜头高度：滚轮（下滚 = 拉高）或 `-`/`=`；`zoomTarget` 存目标值，`zoom` 每帧 `+=(target-zoom)*min(1,9dt)` 平滑逼近，避免跳变
- `render(ctx,{…,zoom})`：`translate(-cam*zoom+shake)` → `scale(zoom,zoom)`；屏幕→世界换算别漏这一层
- `VIEW_ZOOM.min` 由世界尺寸倒推：视口不能占掉地图的一大半（否则镜头推不动、整张图一眼看完、刷怪圈也没地方待）。0.7 → 视口 1829×1029，镜头还能横推 731px
- 画布缓冲 = 舞台 CSS 尺寸 × DPR，`ctx.setTransform(DPR*scale, …)`；逻辑坐标直接画
- 触摸事件必须经 `toLocal()` 换算回逻辑坐标，否则缩放后摇杆会偏
- 敌方单位在**视口外一圈**刷出（不是地图边缘），玩家身后也会来；夹在世界内
- 小地图（右下角）画世界轮廓 + 敌人 + 视野框 + 玩家，用来判断地图大小与身位

## 4.1 调试钩子

浏览器控制台里可直接读写状态（不影响游戏）：

```js
__game.player.speed = 420     // 改数值手感
__game.G.cam                  // 当前镜头
__game.playerScreen           // 玩家在屏幕上的逻辑坐标（正常跟随时≈视口中心）
__game.view                   // { w, h, world }
__game.setZoom(0.75)          // 镜头高度：0.75 拉高 … 1.6 推近（会写 localStorage）
__game.zoom / __game.zoomTarget / __game.viewSize   // 当前/目标缩放、视口在世界里的尺寸
__game.restart()
```

## 4.3 平衡工具与曲线（重要）

浏览器控制台里可以**不出画面地推进模拟**，用来验证数值而不是靠手打：

```js
__game.bot(true)                       // 自动走位机器人（12 方向势场，选最空方向）
__game.sim(60)                         // 推进 60 游戏秒（自动把装备终端选掉，策略=像人一样选）
__game.sim(60, {bench:0})              // 见下：step 可改（1/40 更快，1/60 更准）
__game.snapshot()                      // 局面摘要：等级/血量/DPS/场上敌人/装备
```

批量测一局的模板（MCP/控制台里都能跑）：

```js
for (let r = 0; r < 5; r++) {
  __game.restart(); __game.bot(true);
  while (!__game.G.over && __game.G.t < 1000) __game.sim(30, { bot: true, step: 1/40 });
  console.log(Math.round(__game.G.t / 60) + ' 分钟');
}
```

**实测数据（当前版本，6 局）**：4.2 / 14.1 / 14.1 / 14.2 / 14.8 / 18.5 分钟，中位 **14.2**，均值 13.3。
机器人是"中等水平玩家"的代理（会走位但会失误），真人应在 8–15 分钟。

**平衡是怎么配出来的**（改动数值时照着这个逻辑走）：

1. 先测玩家 DPS 曲线（`snapshot().dps10`）：1 分钟 ~500 → 3 分钟 ~4k → 5 分钟 ~12k，之后在 2 万上下见顶。
2. 刷怪率 `SPAWN.rate(w) = min(13, 2.4 + 0.9w)` × 敌方血量 `ENEMY_SCALE(w)`（生成率上限已从 20/s 降到 13/s，见更新计划 #10 可读性改造） ≈ **0.8×玩家 DPS**，画面才会"装满能杀的敌人"。
3. `ENEMY_SCALE` 在 w>25 后额外递增 `(1 + max(0, w-25)*0.22)` —— 玩家战力 5–7 分钟见顶，靠这段在 10–14 分钟越过它，**保证终局必然到来**（否则满配玩家会无限无伤刷下去，实测过）。
4. `SPAWN.ramp(t)` 开局渐入（0 秒 0.5 倍、110 秒拉满）+ `damagePlayer` 里的**开局伤害宽限**（0 秒 45%、120 秒拉满）：这两条一起把"单局时长两极分布（3 分钟死 or 无限活）"修成了稳定分布。
5. 武器不足 3 把时**保底必出新武器**（pity），避免开局连抽不到武器直接崩盘。
6. 关键教训：**击杀回血必须限速**（`killHealAcc`，每秒最多 5% 最大生命），否则后期每秒几十杀 = 每秒回几百血 = 无敌。



| 层 | 位置 | 说明 |
|---|---|---|
| 实体半径 | `config.js`（`PLAYER.r` / `ENEMY_TYPES[x].r` / `BOSS.r` / `ORB.r` / `PICKUP.r`）+ 弹体半径用各武器的 `WEAPONS[x].bulletR` | 同时决定碰撞与外观 |
| 视觉膨胀 | `render.js` 的 `GLOW_K`(0.68) 与 `TEXT_K`(0.78) | 发光光晕与飘字字号统一收缩，避免改几十处调用点 |

## 5. 美术与渲染管线

画面 = **世界空间绘制 → 屏幕空间后处理**。世界照旧直接画在主画布上，后处理在末尾叠（不需要离屏场景画布）：

| 层 | 位置 | 说明 |
|---|---|---|
| 底色 | `render()` 开头 | 径向渐变（屏幕空间） |
| 景深背景 | `drawBackdrop()` | 三层无缝平铺贴图：星云(视差 0.05)/远星(0.22)/近星(0.45)，启动时烘焙一次，每帧只做 3 次 pattern 填充 |
| 世界网格 + 世界边框 | 世界空间 | 跟着镜头滚，颜色取调色板 B0 背景带 |
| 单位 | `unitSprite()` / `drawUnit()` | **烘焙贴图**：剪影 + 前亮后暗体积 + 亮心，每帧一次 `drawImage`（比原来每帧 4–8 次 path 更快也更好看） |
| 特效 / 粒子 | 世界空间 | 霓虹绘制，`lighter` 叠加发光 |
| 辉光 bloom | `compose()` | 主画布 → 1/4 缩略图 → 阈值 → **乘回原色** → 模糊 → `lighter` 叠回 |
| 暗角 vignette | CSS `#vignette` | 走合成器，canvas 里一趟全屏填充的成本直接省掉 |
| 全屏闪光 | `render()` 末尾 | 放在 bloom **之后**，否则闪白会被二次放大 |

### 5.1 调色板与可读性（按威胁能级分带）

所有战斗颜色集中在 `config.js` 的 `PALETTE`，规则是**明度分带 + 形状区分**：

| 带 | 灰阶 | 谁 | 含义 |
|---|---|---|---|
| B0 | 14–75 | 背景、网格、世界边框 | 只提供纵深，不许抢注意力 |
| B1 | 230+ | 玩家核心、敌方弹幕核心 | 顶点，只有"最该被看见的"能用 |
| B2 | 190–200 | 玩家本体与光环 | **玩家永远最亮的那一档** |
| B3 | 90–190 暖琥珀 | 炮塔、预警提示色 | 能杀你的东西才用暖色 |
| B4 | 128–156 | 经验碎片、道具、Boss、突袭/拦截 | 前景事件 |
| B5 | 80–178 冷灰 | 巡逻机、重装机兵、分裂机 | 小兵：靠数量和形状说话，故意压暗 |

**注意（2026-09 玩家反馈后调整）**：**敌方弹幕已统一改成红色**（`PALETTE.enemyBullet = #FF3B30`，核心近白 `#FFE6DC`）——
玩家要求"敌人弹幕换成红色"，因此它不再落在 B3 的暖琥珀段。代价是色盲最坏对比从 9.68 掉到 2.48（低于 3:1），
可读性改由**近白色核心 + 拖尾**承担。要回退只需改 `PALETTE.enemyBullet` / `enemyBulletCore` 两处（全部弹幕都走 `fireBullet` 这一个入口）。
`#FFB020` 现在只用于"下一波精英/陨级"的 HUD 预告与帧率告警，不再是弹幕色。

校验脚本：`node bench/palette-check.mjs` —— 会对全部颜色做 protan/deutan/tritan 三种色盲模拟，断言**跨带明度差 ≥20**，并把同带内"必须靠形状区分"的列出来。

**两条踩过的坑（都是"光心写死白色"造成的分带失效）**：
1. `unitSprite()` 里每个单位都给了纯白核心 → 实测所有单位峰值全在 233–242，玩家和金鱼小兵一个亮度，规则当场失效。现在核心用**本体的亮边色**，白色只留给玩家核心与敌方弹幕核心。
2. `getGlow()` 的光心原来写死 `rgba(255,255,255,0.95)` → 凡是画过光晕的东西（碎片、弹幕、精英）峰值都被顶到 ~240。现在光心是**提亮后的本色**。

**验证方法**（改完颜色必跑）：`__game` 里读出玩家屏幕坐标，用 `G.enemies` / `G.enemyBullets` / `G.orbs` 的世界坐标换算成屏幕坐标，再在 canvas 上取每个实体 7×7 的最亮像素 → 应该看到一条清晰的阶梯，而不是一堆 240。当前实测：玩家 245 ≥ 敌方弹幕 245 > 经验碎片 ~200 > 突袭/拦截 182–186 > 炮塔 171 > 巡逻 151 > 重装 134。

- 三个后处理开关：`__game.fx = { bloom, backdrop, vignette }`（控制台实时改）
- bloom 参数（都在 `render.js` 顶部，改完请用 `bench/bloom-bench.html` 或 rAF 采样复测）：
  | 常量 | 值 | 为什么 |
  |---|---|---|
  | `GLOW_DOWN` | 4 | 1/2 到 1/16 的开销差不到 1ms（成本按"趟"算不按像素算），所以按画质选 1/4 |
  | `BRIGHT_FILTER` | `brightness(2) contrast(4)` | 起效亮度 0.19、过渡带 0.125；过渡带太窄会出现硬边/闪烁 |
  | `GLOW_BLUR` | 3 | 单位是**图层像素**，等效全分辨率 12px；`blur` 半径本身几乎不花钱 |
  | `GLOW_ALPHA` | 0.5 | 0.85 会把暗部整体洗白（踩过）；想要更强就多叠一趟而不是调大 alpha |
  | `GLOW_PAD` | 10 | 图层四周留白，否则贴着屏幕边的光晕会被切平 |
- **保留颜色那趟（`multiply`）不能省**：只有阈值的话，所有光晕都是白的，霓虹的青色/橙色全丢；乘回原图后光晕是彩色的（实测"半亮且带色"的像素 +24%）
- `ctx.filter` 在旧 Safari 上不存在 → `typeof glowCtx.filter === 'string'` 检测，不支持就整段跳过 bloom（画面只少一层辉光，不报错）
- **别退回"离屏场景画布 + 整体合成"的写法**：那要多一次全屏 blit，等于整个 bloom 的预算
- 背景亮度刻意压低（星云层 alpha 0.2）：背景只提供纵深，不许跟弹幕抢注意力。改完用亮度直方图核一遍——目标是大片真正的黑 + 极少量高亮
- 调研细节与实测表：`docs/canvas2d-bloom-report.md`（外部技术报告的完整版），基准页 `bench/bloom-bench.html`（自包含，双击可跑）

### 5.2 打击感与特效

- **击杀冲击波**（`game.js` 击杀分支）：只给"值得看一眼"的单位 —— 重装/分裂（r≥10）用冷灰细环，精英/Boss 用金/粉大环并带屏幕震动。**小兵不给环**：一秒死十几个，人人一圈的话整屏都是白圈，那叫噪点不叫打击感。
- **受击闪白**：单位贴图有两套（本色 / 全白），`e.flash > 0` 时直接换贴图，不做路径重绘。
- **拖尾**：我方与敌方弹幕都有短拖尾。弹幕游戏里玩家读的是**轨迹**——没有拖尾时 4px 圆点会突然出现在脸上。
- **增益分级**：散射/爆炸粒子沿用 `G.parts` 上限（`MAX_PART`），别为了好看把上限抬掉。

**一个容易反复踩的坑：加法混合下的"峰值饱和"**。`lighter` 会把 glow + 本体 + 核心叠起来，任何"发光 + 有实体 + 有核心"的东西峰值都会顶到 250–255（我方弹幕、敌方弹幕、玩家都是）。这不是 bug，是霓虹加法渲染的固有结果——**所以弹幕之间的区分靠色相（冷 vs 暖琥珀）和形状，不靠亮度**；亮度分带只对"单层绘制"的东西（单位、碎片）有效。

## 5.4 图标与武器射程

**图标**（`src/icons.js`）：全部改成 **24×24 内联 SVG**（1.7px 描边 + 22% 透明填充，颜色跟随调用方），替换原来的 emoji。
emoji 的问题不是好不好看，而是**不可控**：字形/配色由系统字体决定（Windows/Mac/Android 三套不同），而且自带颜色（黄色的 🛡️、彩色的 🦠）会和调色板的威胁分带打架。现在武器图标用武器自己的颜色，属性/模组用 UI 主色，`iconFor()` 查不到时退回 emoji（新增内容不会变空白）。

**射程**：以前是隐式的、且**账是错的** —— 面板读不出来，`flak` 写 `range: 340` 但实际 `780×0.3 = 234`，`dart` 名义 1440 但弹体在视口外 220px 就被回收（真实上限 ~860）。现在：

| 规则 | 说明 |
|---|---|
| 唯一事实来源 | 每个武器写 `range`（世界像素，从机体算起）；`bulletLife = range / bulletSpeed` 由它推出来，不再各写一个 |
| orbit / nova / laser | 由几何决定：`radius + hitR` / 最大冲击波半径 / 光束长度；统一用 `weaponRange(id, lv)` 取，面板与自检同一个入口 |
| 索敌 | `nearestEnemies(n, range)`：够不着的目标不开火。实测只有 **1.3%** 的帧会因此待机（那种情况下最近的敌人也在 665px、打了也够不着） |
| 弹体回收边距 | `BULLET_CULL_MARGIN = 420` —— 必须 ≥ 最长射程 − 视口半高（780 − 360），否则上下方向飞不到面板写的距离（射程是圆、视口是矩形） |
| 面板 | 武器卡多一条射程条（宽度 = 射程 / 全武器最大射程）+ 数字；构筑栏的 tooltip 也带射程 |

**射程是实测值不是拍脑袋**：
- 扇形武器（`flak` 扩散 0.8rad、`dart` 0.12rad）在边缘会因为扩散打不中单点目标，所以这两个数是量出来的：`dart` 620（690 就打不中了）、`flak` 180（200 打不中）。
- 自检脚本：把单个静止目标摆在 `射程×0.9` 与 `射程×1.15`，跑 6 秒，要求**前者掉血、后者一滴不掉**。当前 11 把武器全部通过（新增的天基炮用落点半径核对）。
- **改任何射程都要重跑这条**，否则面板会重新变成谎话。

## 6. 扩展点：要加东西时改哪里

| 想做什么 | 改哪 |
|---|---|
| 加一把武器 | `config.js` 的 `WEAPONS` 加一项（dmg/cd/num/desc/color，环绕类再加 radius/speed）→ `game.js` 的 `updateWeapons` 加一个分支 → 需要新画法时加 `render.js` |
| 加一种敌人 | `config.js` 的 `ENEMY_TYPES` 加一项 → `game.js` 的 `spawnEnemy` 刷新权重 → `render.js` 的绘制分支 |

| 改 HUD 读数 | `index.html` 加元素 → `game.js` 的 `updateHUD` 赋值 → `theme.css` 样式 |

## 6.1 音效 / 暂停 / 纪录

- **音效**：`src/audio.js` 用 WebAudio 实时合成，零音频文件。浏览器要求首次用户操作后才能出声，所以在 `keydown` / `touchstart` 里调 `audio.unlock()`。同一瞬间的声音有预算（每 60ms 16 点），弹幕密集时多余的音会被丢弃，不会糊成噪音墙。
- **暂停**：`ESC` 切换 `pausedManual`（与装备终端的 `G.paused` 相互独立，`loop()` 里两者都要检查）。
- **静音**：`M` 键；标签同步在 `syncMuteLabel()`。
- **最高纪录**：`localStorage['starfall.best.v1']` 存 `{t, kills, level, wave}`，结算面板对比后显示「★ 新纪录」或「历史最佳」。

### 设计原则（照抄自案例复盘，改玩法时别违背）

1. **威胁压缩**：普通怪一个怪只回答一个问题（近战触碰 = 背景音；远程/特殊 = 前景信号；精英 = 强制事件）。当前比例：近战触碰 5 类、远程 1 类 —— 远程别超过四成。
2. **注意力分配**：绝大多数怪的价值是"被收割"而不是"威胁玩家"；让所有怪都喊"看我"等于没有怪被看见。
3. **节奏编排**：节拍必须**可预期** —— "随机的困难让玩家焦虑，可预期的困难让玩家投入"。所以波次类型与倒计时是明示的，Boss/精英波固定在第 5/3 波倍数。
4. **难度曲线**：0–3 分钟温和（教学）→ 3–10 分钟线性加压 → 10 分钟后指数收尾（`ENEMY_SCALE` 的 w>25 递增段）。


## 7. 不变式（改动时别破坏）

1. `config.js` 不 import 任何模块，保持纯数据 + 纯函数
2. `render.js` 只读 `G` / `player`，绝不改状态
3. 世界尺寸恒定 2560×2560，不随窗口变化；触摸坐标必须换算
4. 实体半径在 `config.js`，视觉缩放在 `render.js` 的 `GLOW_K` / `TEXT_K`
5. 装备终端打开时必须暂停世界（`G.paused`），选择后必须恢复，且支持连升多级排队
6. 零资源文件：不加载任何图片 / 音频 / 字体 / 外部依赖
7. **越界回收一律按「视口外一段距离」判断，禁止再用 `W` / `H` 当世界边界** —— 血的教训：改大世界时漏改子弹回收，子弹一生成就被删，玩家一整局打不出伤害
8. 移动是「角加速度转向」模型（见 4.2），不是在速度向量上做分量插值
9. 所有「每帧阻尼」用 `frameDrag(系数, dt)` 换算，保证 144Hz 与 60Hz 手感一致
10. **碰撞一律走空间网格**（`forEachNear` / `forEachNearBox`），禁止再写 `for (const e of G.enemies)` 全量扫描 —— 敌人上限 260（曾为 420，可读性改造后下调），全量扫描会打穿帧率（网格化后每帧逻辑从数毫秒降到 0.03ms）。
    例外允许：**每帧一次**的整体统计（例如统计"正在预瞄的狙击机"数量）—— 那是 O(n)，不是 O(n²)
11. **粒子/飘字必须有上限**（`MAX_PART` / `MAX_TEXT`），实体容器的删除**优先**用 `swapRemove`（当前：texts/parts/bolts/rings/beams 用它；bullets/enemyBullets/zones/pickups/orbs/enemies 仍是倒序 `splice`，因为需要按索引乱序删除）—— 原来的 `splice` 在几百个对象同时过期时是 O(n²)，一颗战术弹就能造出数千粒子
12. **刷怪点必须落在视口外**：垂直方向那条边**不能 clamp 进世界**，否则相机贴边时怪会生成在画面里（贴角时甚至落在玩家接触距离内）
13. **失焦/切后台必须清空按键并自动暂停**（`blur` + `visibilitychange`），回到前台时自动继续 —— 浏览器失焦时不派发 keyup，否则切回来会发现自己在一直滑行；自动暂停只在 `pauseReason === 'blur'` 时自动解除，玩家按 ESC 的暂停不能被焦点事件吃掉
14. **代价装备的自损不能致死**：过载反应堆最多把生命压到 25%，否则玩家会静默自杀且无从归因（实测：压到 1 血后任何一发弹幕都秒杀）
15. **面板打开时 ESC 不抢输入**、`keydown` 的自动重复事件必须忽略（否则长按 1 会替玩家把后续每一级都选掉）
16. **任何用到"一屏多大"的地方都必须走 `viewW()` / `viewH()`**（相机、刷怪圈、剔除、回收、小地图视野框、Boss 刷怪点）。裸用 `W`/`H` 只在 zoom=1 时才对；拉高镜头时会把"屏幕外"算成"屏幕内"
17. **改 `WORLD` 必须重跑单局时长**：这张地图的终局是"边界把人逼到角落"形成的，地图一大，纯走位就能无限跑 —— 2560 是实测过的上限（3072 会出现跑满 25 分钟不死的不死局）。配套的第二个旋钮是 `ENEMY_SPEED_SCALE`（敌人后期必须比玩家 340 更快）

- **内容**：更多 Boss 型号、武器进化（两把满级武器合成）、地图装饰物
- ~~元进度~~：**已实现**（`starfall.meta.v1`：累计战绩 + 局外信用点 + 5 项永久强化，见图鉴 §9）

- **想要更大的地图**：得先补一个替代"边界"的收束机制（安全区逐波收缩 / 包围式刷怪），否则 2560 以上会出现跑满 25 分钟不死的局（已实测）

- **换引擎的触发条件**：单帧实体数要上到 2000+，或者需要真正的着色器效果（法线/扭曲/多尺度 bloom）时才值得换。当前 420 敌人下 p50 4.2ms，canvas 2D 还有 4 倍余量
