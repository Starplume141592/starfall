# 星陨 · 改造设计（以 Demo 为主体 · 科幻）

基线：`index.html`（单文件 canvas 2D 幸存者 Demo，已落盘可直接运行）。
原则：**Demo 的循环、手感、视觉基调都是资产，一律保留；只换题材与系统命名。**

## 0. 世界观（一句话）

> 你是深空残骸带里一台实验型作战单元。击毁敌机、吞噬残骸、就地重组武器库——直到被下一波「劫」淹没。

视觉基调：**沿用 Demo 现有的深色霓虹科幻**（深底 `#07090d` + 径向暗角 + 描边发光 + 速度拖尾 + 粒子）。
不做风格重做，只做科幻质感强化（见 A）。**不做水墨。**

## 1. 保留 vs 改造

| 保留（完全不动） | 改造（只改命名与文案） |
|---|---|
| 主循环：移动 → 自动攻击 → 拾取 → 三选一 → 波次 → Boss | 题材：现代武器 → 科幻武器库 |
| 手感：惯性移动、hitstop、震屏、拉伸拖尾、连杀 | 等级：Lv → 机体型号 `Mk-I…` |
| 视觉：深色霓虹、发光描边、拖尾、粒子、网格 | 掉落：心/磁力/炸弹 → 纳米修复包/引力场/战术弹 |
| 敌人行为：追踪/冲刺/分裂/远程/Boss 状态机 | 波次文案：配合「劫」的世界观 |
| 数值骨架：`expNeed`、波次曲线、伤害/冷却公式 | HUD 文案：Lv/波次/时间/击杀 → 型号/波次/时间/击杀 |

## 2. 改造线

### A. 科幻质感强化（轻量，不换风格）
- HUD 从玻璃拟态卡片 → **终端风**：等宽字体、边框角标、画布底部叠一层极淡扫描线
- 三选一面板 → 「**装备终端**」语气（标题 `装备终端 // 选择升级`）
- 单位配色分层（沿用现有色板，只做归类）：
  巡逻机=青 `#58a6ff`｜拦截机=橙 `#ffa94d`｜重装机兵=紫 `#9775fa`｜突袭机=橙红 `#ff8c42`｜分裂机=青绿 `#4ecdc4`｜炮塔机=蓝紫 `#b197fc`｜劫级=品红 `#f06595`
- 玩家拖尾 → 称呼为「引擎尾焰」（实现不变）
- 明确不做：水墨、宣纸、墨晕、飞白

### B. 题材改造：武器库替换
| 现 | 改 | 机制（保留不变） |
|---|---|---|
| 飞镖 | 蜂群导弹 | 追踪多发 |
| 环绕球 | 卫戍无人机 | 环绕 |
| 链锯 | 等离子刃环 | 贴身旋转 |
| 冲击波 | 电磁脉冲 EMP | 环形爆发 |
| 闪电 | 链式电弧 | 链式跳跃 |
| 激光 | 粒子长矛 | 穿透直线 |
| 回旋镖 | 回旋切割器 | 去回穿透 |
- 追加「带代价的装备」：**过载反应堆**（伤害极高，持续自损）、**纳米虫群**（伤害低，击杀回血）、**近防霰弹**（扇形短程巨推力）
- 敌人 → 机械单位：**巡逻机 / 拦截机 / 重装机兵 / 突袭机（冲刺）/ 分裂机（死亡裂成 2 小机）/ 炮塔机（远程）**
- Boss → **「劫」级装甲核心**：状态机不变（追击 → 蓄力预警 → 高速突进 → 撞墙瘫痪，受伤 ×3）

### C. 系统改造：机体型号 / 数据残片 / 纳米修复
- **等级** → 机体型号：`Mk-I → Mk-II → … → Mk-IX`，替换 HUD 的 `Lv`
- **大突破**：每 9 级一次「**超频跃迁**」（波次结算触发），给一次四选一
- **型号跃迁**：Mk 系列 → 精英型 → 指挥型 → 泰坦型 → 母舰核心
- **经验球** → 数据残片（吸附手感原样保留）
- **掉落**：纳米修复包 +35 / 引力场发生器（全图吸取）/ 战术弹（全屏 300 伤害）
- **波次** → 保留「第 N 波」，Boss 每 5 波 = 一个「劫」

### D. 结构改造：单文件 → 分层（仍不需要打包器）
浏览器原生 ES module，`index.html` 用 `<script type="module" src="./src/game.js">`：
```
src/
├── game.js        主循环 + 装配
├── config.js      WEAPONS / STATS / ENEMIES / 曲线（纯数据，无逻辑）
├── state.js       reset() 与全局状态
├── systems/       player / weapons / enemies / spawn / boss / pickup
├── render/        实体绘制（沿用现有霓虹画法，只按单位归类）
└── ui/            HUD 与装备终端面板（保留现有 DOM 写法）
```
> 拆分的唯一理由是**让 AI 改得动**：700 行单文件改到第四轮必然开始互踩。纯数据进 `config.js` 后，调数值不动逻辑。

### E. 手感（只加不减）
- 保留 hitstop / 震屏 / 惯性 / 连杀
- 可加（低成本高收益）：暴击顿帧、拾取吸附的粒子拖线、超频跃迁的全屏闪白

## 3. 分轮交付计划

| 轮次 | 内容 | Owner | 验收 |
|---|---|---|---|
| R1 | 结构拆分（D）+ 配置表外提（含 B 的科幻数据） | 两个 AI 各领一半 | 拆分后浏览器直接跑通，行为与现版一致 |
| R2 | 科幻质感强化（A：HUD 终端化 + 单位配色分层） | 视觉 owner | HUD 变终端风，单位配色与表格一致 |
| R3 | 武器库/机械单位替换（B） | 两个 AI | 7 武器 + 6 单位 + 劫级 Boss 命名与描述到位 |
| R4 | 机体型号与掉落系统（C） | 系统 owner | HUD 显示 `Mk-III`，跃迁有面板 |
| R5 | 手感补充（E）+ 数值平衡 | 两个 AI | 单局 8–15 分钟，静止 3 分钟不死 |

> R1 与 R2 建议合并：R2 只改 HUD 与配色表，跟 R1 拆出来的 `ui/` 与 `config.js` 是同一批文件，一起做省一轮。

## 4. 硬性约束（发给 AI 时必须带上）

- 零美术资源：不加载任何图片/音频/字体文件，一切 canvas 程序化
- 不新增依赖，不用打包器（原生 ES module + `scripts/serve.mjs`）
- 数值一律进 `config.js`，逻辑里禁止硬编码
- 每轮只改自己名下文件，不跨文件重写
- 中文注释；改完必须能刷新浏览器直接复现
- **术语统一**（避免 AI 各写各的）：机体型号 `Mk-I`、数据残片、纳米修复包、引力场发生器、战术弹、陨级单位、超频跃迁、装备终端
- **视觉禁区**：水墨 / 宣纸 / 墨晕 / 飞白 —— 一律不许出现

## 5. 命名

项目名定为 **星陨**（`package.json` → `starfall`，页面 `<title>` → 星陨）。深空残骸带里「陨」既是坠落也是陨铁，与满地的「数据残片 / 残骸」同源；Boss 为「**陨**级装甲核心」。
