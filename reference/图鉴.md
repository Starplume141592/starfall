## 如何使用本图鉴

1. **数值分三层，别混**：
   - **面板值**（`config.js` 原始值）：例如蜂群导弹 Lv7 的 `82` 伤害。这是游戏内卡片上写的数字。
   - **结算值**：实战伤害 = `面板伤害 × player.dmgMul`，实战冷却 = `面板冷却 × player.cdMul`，暴击再 ×2。玩家基础 `dmgMul = 1.3`、`cdMul = 0.9`，所以**开局就比面板高 30% 伤害、快 10% 冷却**。
   - **实战值**：还要乘命中率、穿透、溢出、敌人减伤/瘫痪倍率。本文只在明确标注处给理论 DPS（`伤害 × 数量 ÷ 冷却`），那是**上限**而不是期望值。
2. **每个表上方都标了来源**（如 `config.js: WEAPONS`）。看到来源就能自己去核。
3. **机制性数字一律给常量名**（如 `ZONE.max`、`BULLET_CULL_MARGIN`），方便回源码搜索。
4. 想自己复现：跑 `node bench/codex-tables.mjs`（全量）或 `node bench/codex-tables.mjs weapons`（只看武器）。该脚本就是为"改完 `config.js` 后重算本文所有会变的数字"而写的。
5. 自检脚本：**`npm run check`** 一条命令跑完两个门禁（`node bench/weapons-check.mjs` + `node bench/palette-check.mjs`）；数值速查表用 `npm run tables`（`node bench/codex-tables.mjs`）。两个门禁的**首行**就是结论（`✓` / `✗`），退出码非零即失败。
6. 术语按源码口径：**数据残片**（经验掉落）、**超频跃迁**（每 9 级的四选一模组面板）、**陨级单位**（Boss 的显示名）、**精英波**（每 3 波的强制精英批次）、**信用点**（分「局内」与「局外」两套，不通兑）。

> **本目录里的两处编号调整**：规范里「16」是附录；因为新增了「**16. 已发现的不一致**」这一节（对开发最有价值的信息不该埋在附录后面），附录顺延为 **17**。

### 3.2 机体（SHIPS，开局三选一）

来源：`config.js: SHIPS`；有效生命 `EHP = hp / (1 - dr)` 由脚本算出。机体差异**只在单局内生效**，不做解锁、不碰存档，只记住上次选择（`localStorage['starfall.ship.v1']`）。

| 机体 | tag | 招牌武器 | 最大生命 | 减伤 dr | EHP | 移速 | 伤害倍率 | 冷却倍率 | 暴击 | 拾取范围 |
|---|---|---|---|---|---|---|---|---|---|---|
| 游隼 `falcon` | 均衡 | 蜂群导弹 `dart` | 150 | 0% | 150 | 340 | ×1.30 | ×0.90 | 5% | 130 |
| 壁垒 `bulwark` | 厚血 | 近防霰弹 `flak` | 230 | 12% | **261** | **292.4**（×0.86） | **×1.15** | ×0.95 | 5% | 120 |
| 疾风 `zephyr` | 纸皮高机动 | 等离子刃环 `saw` | **110** | 0% | 110 | **408**（×1.20） | ×1.30 | **×0.85** | **13%**（+8%） | **190** |

机体字段与基准 `PLAYER` 的关系（`game.js: reset()`）：

```
hp    = (ship.hp    || PLAYER.hp)    + mb.hp
speed =  PLAYER_SPEED * (ship.speedMul || 1)
dr    =  ship.dr || 0
crit  =  PLAYER.crit + (ship.crit || 0)
pickupRange = (ship.pick || PLAYER.pickupRange) + mb.pick
dmgMul = (ship.dmgMul || PLAYER.dmgMul) + mb.dmgMul
cdMul  = (ship.cdMul  || PLAYER.cdMul ) * mb.cdMul
```

> 注意 `dmgMul` 是**加法**叠加局外加成，`cdMul` 是**乘法**。`bulwark` 的 `dmgMul: 1.15` 会把基准的 1.3 **覆盖成 1.15**（更低），这是"重装机体换伤害"的代价，不是笔误。

### 3.3 移动手感

来源：`config.js: PLAYER_SPEED / ACCEL_* / TURN_*`；`game.js: update(dt)` 移动段

| 常量 | 值 | 含义 |
|---|---|---|
| `PLAYER_SPEED` | 340 | 目标速度（px/s）；横穿一屏（1280px）3.76 秒，横穿地图（2560px）7.53 秒 |
| `ACCEL_UP` | 26 | 有输入时的速度靠拢率（`k`） |
| `ACCEL_DOWN` | 16 | 松手滑行的靠拢率 |
| `ACCEL_BRAKE` | 34 | **反向输入**（`vx*mx + vy*my < 0`）时的靠拢率，掉头不拖泥带水 |
| `TURN_ACCEL` | 10 | 基础转向角加速度（rad/s） |
| `TURN_BIG` | 1.6 | 大角度额外倍率（180° 掉头 ≈ 2.6 倍） |
| `TURN_RATE` | 26 | 机体**朝向**（纯视觉）跟随速度方向的速率 |

实际公式：
```
targetSpeed = m > 0 ? player.speed * speedScale : 0
k           = m > 0 ? (reversing ? ACCEL_BRAKE : ACCEL_UP) : ACCEL_DOWN
nextSpeed   = curSpeed + (targetSpeed - curSpeed) * min(1, k * dt)
agility     = 1 + (1 - min(1, curSpeed / player.speed)) * 0.9      // 低速更灵
bigTurn     = 1 + TURN_BIG * (|da| / PI)                            // 大角度转得更快
maxTurn     = TURN_ACCEL * agility * bigTurn * dt
cur        += clamp(da, -maxTurn, maxTurn)                          // 方向按角速度转，不是分量插值
```
- 触屏 `speedScale = clamp(touch.mag, 0.35, 1)`——**下限 0.35 防"轻碰不动"的粘滞感**。
- 速度 < 1 时方向直接取输入方向（没有方向可言时不做无意义旋转）。
- 撞到世界边界：位置夹在 `[player.r, WORLD - player.r] = [8, 2552]`，**对应轴速度归零**。
- 朝向跟随仅在 `spd > 25` 时生效。
- 尾焰粒子：速度 > 100 时每 0.055 秒一颗，颜色 `#58a6ff` / `#9fd5ff`。

### 3.4 受伤、无敌帧与减伤

来源：`game.js: damagePlayer(dmg, src)`

```
if (player.invuln > 0 || G.over) return;                  // 无敌帧内完全免疫
if (player.shield && player.shieldCd <= 0) { …相位抵挡，直接 return… }
grace = Math.min(1, 0.45 + G.t / 120);                    // 开局伤害宽限
real  = Math.max(1, dmg * grace * (1 - player.dr));       // 最低 1 点
player.invuln = PLAYER.invuln;                            // 0.7 秒
```

| 机制 | 值 | 说明 |
|---|---|---|
| 开局伤害宽限 `grace` | 0s → **0.45**；30s → 0.70；66s → **1.00**；之后 1.00 | `min(1, 0.45 + t/120)` |
| 减伤上限 | **0.60** | `armor` 卡 `p.dr = Math.min(0.60, p.dr + 0.10)`；机体 `bulwark` 自带 0.12 |
| 无敌帧 | 0.7 秒（`PLAYER.invuln`） | 受伤与相位抵挡都会重置 |
| 最低伤害 | 1 点 | `Math.max(1, …)`，所以减伤堆满也挡不住滴血 |
| 相位护盾 | `shieldCd = 10`（秒） | 见 6. 模组；**代码注释写的是 8 秒，与实现不符**（第 16 节） |
| 受伤表现 | 震屏 4、全屏 `flash(.3, '255,60,60')`、飘字 `-N`、粒子 10 颗 | `game.js` |
| 无敌视觉 | 5Hz **呼吸式**透明度脉动（0.55 ~ 1.0） | 原为 `floor(invuln*20)%2`（20Hz 硬翻转，落在光敏峰值频段） |

### 3.5 击杀回复（吸血）的限速

来源：`game.js: hurtEnemy()` 击杀分支

```
healOnKill = player.killHealFlat(噬能涂层 0.6/级) + Σ 已装备武器的 onKillHeal(lv)（纳米虫群）
if (G.t - player.killHealAt > 1) { player.killHealAt = G.t; player.killHealAcc = 0; }   // 每秒重置窗口
cap   = player.maxHp * 0.05          // 每秒最多回 5% 最大生命
allow = max(0, cap - player.killHealAcc)
real  = min(healOnKill, allow)
```

> 设计注记（源码原文）："否则后期每秒几十杀会变成无敌。所有吸血途径都必须汇进这一条限速里。"

### 5.0 通用规则（先读这一节）

来源：`config.js: WEAPONS / weaponRange() / bulletLife()`；`game.js: updateWeapons()`

| 规则 | 实现 |
|---|---|
| 等级映射 | `L(lv) = 1 + (lv-1) * (4/6)`、`N(lv) = round(L(lv))`；`maxLv = 7`，`L(7) = 5` —— **7 级铺满，但满级战力与旧 5 级完全一致** |
| 射程是第一等属性 | 每把武器写 `range`（世界像素，从机体算起）；`bulletLife = range / bulletSpeed` 由它推出 |
| 射程统一入口 | `weaponRange(id, lv)`：`orbit → radius + hitR`；`nova → radius(lv)`；`laser → len`；其余 → `range` |
| 面板射程条分母 | `MAX_WEAPON_RANGE = max(weaponRange(id, 5)) = 780`（粒子长矛） |
| 索敌 | `nearestEnemies(n, range)`：**够不着的目标不开火**；无目标时把计时器压到 0.08/0.1 秒后重试 |
| 实战伤害 | `def.dmg(lv) * player.dmgMul`；暴击再 ×2；敌人 `vulnMul > 1` 时再乘 |
| 实战冷却 | `def.cd(lv) * player.cdMul` |
| 单次齐射 / 理论 DPS | 下表 `burst = 伤害 × 数量`、`dps = burst / 冷却`。**不含** `player.dmgMul/cdMul`、穿透溢出、命中率、DoT |

|---|---|---|---|---|---|---|---|
| `L(lv)` | 1 | 1.6667 | 2.3333 | 3 | 3.6667 | 4.3333 | **5** |
| `N(lv)` | 1 | 2 | 2 | 3 | 4 | 4 | **5** |

| 概率速查 | w4 = 5.9%，w5 = 7.0%，w10 = 12.5%，w14 = 16.9%，w20 = **23.5%**，w≥23 起封顶 **26%** |
| 生命 | `hp = maxHp = round(hp * 3.2)`（`ELITE.hpMul`） |
| 半径 | `r = round(r * 1.35)`（`ELITE.rMul`）：巡逻机 8→11、拦截机 6→8、重装机兵 12→16、突袭机 8→11、分裂机 10→14、炮塔机 7→9、狙击机 8→11 |
| 经验 | `exp = round(exp * 4)`（`ELITE.expMul`）：巡逻机 12、拦截机 18、重装机兵 36、突袭机 18、分裂机 24、炮塔机 18、狙击机 30 |
| 伤害 | `e.dmg *= 1.4`（`ELITE.dmgMul`，只影响接触伤） |
| 外观 | 金色 `#F0E442` 旋转虚线圈（`r + 6`）+ 外发光 |
| 环形弹幕 | 每 `ELITE_BURST.every = 4.2` 秒，若 `d < 620` 则放 **8** 发环弹（见 8.3） |
| 掉宝箱 | 精英死亡有 **12%**（`ELITE_DROP_CHEST`）掉宝箱（吸附范围 `CHEST_MAGNET_RANGE = 620`） |
| 残片数量 | 精英/Boss 爆 **4 颗**（普通怪 1 颗），总经验不变 |

**精英波（事件）** vs **随机精英化**：

| | 精英波 | 随机精英化 |
|---|---|---|
| 触发 | `G.wave % SPAWN.eliteWaveEvery(3) === 0`，**且不是 5 的倍数**（Boss 优先） | 每次 `spawnEnemy()` 时按 `ELITE.chance(w)` 掷 |
| 规模 | `n = SPAWN.eliteWaveCount(3) + floor(max(0, wave - 12) / 12)` | 1 只 |
| 支付信用点 | **是**（`e.paysCredit = true` → 每只 `CREDIT.elite = 3`） | **否** |
| 是否编队 | 不叠加小队逻辑（`forceElite` 时跳过） | 随机 |

精英波规模台阶：w3–21 → **3 只**；w24–35 → **4 只**；w36–47 → **5 只**；w48+ → **6 只**（每 12 波 +1）。

**可读性约定**（`render.js`，源码注释称为"铁律"）：
- 预警线 = **线宽由细到粗 + 亮度由暗到亮**地"充满"：`lineWidth = 2 + LASER.width*2*k = 2 + 30k`，alpha `0.18 + 0.35k`；叠一条白线 `1 + 2k`。
- 枪口有**充能环**（半径 `e.r + 4 + 4*(1-k)`），回答"是谁在瞄我"。
- 同步 `audio.warn()`（1500→2200Hz，0.08 秒）—— 听觉预警与视觉预警同时给。
- 并发上限 3 的**实现方式**：每帧 O(n) 统计一次 `aimingSnipers`，**绝不在每只怪内部再扫一遍敌人表**（那会变成 O(n²)，违反性能契约）。

### 8.6 区域封锁（壁垒者 / 相位者 / 天基炮）

来源：`config.js: ZONE`；`game.js: spawnZones()`、`zones` 循环

| 常量 | 值 | 含义 |
|---|---|---|
| `telegraph` | **1.2 s** | 预警时长 |
| `r` | **96** | 爆炸半径（固定，不随波次变） |
| `life` | 0.35 s | 爆炸后的白色闪光时长 |
| `dmgMul` | **1.6** | 伤害 = `e.dmg × 1.6` |
| `max` | **8** | 场上预警圈上限 |

| 用户 | 用法 |
|---|---|
| 壁垒者 `slam` | `spawnZones(player.x, player.y, 3, e.dmg * 1.6)` —— 3 个圈，**第一个 `dist = 0` 直接压在玩家脚下**，其余在 `rand(60, 180)` 半径上错开，逼你提前选路线 |
| 相位者 `blink_prep`（阶段 2+） | `spawnZones(oldX, oldY, 1, e.dmg * 1.6)` —— 在**离开的位置**留 1 个圈 |
| 天基炮（玩家） | 直接 `G.zones.push(...)`，`ally: true`、`color: def.color`（金）、`r = def.radius(lv)`、`knock 300` |

**爆炸判定**（`game.js`）：
```
敌方圈：d < z.r + player.r  →  damagePlayer(z.dmg, 'zone')
                              player.vx += dx/d * 260; player.vy += dy/d * 260   // 炸飞
                              burst 26 颗、震屏 9、粉色闪光 0.16
己方圈：forEachNear(z.x, z.y, z.r + 24) → ed < z.r + e.r 的敌人吃 z.dmg 并以 300 击退
                              burst 34 颗、震屏 12、金色闪光 0.14、金色冲击环
```

**可读性约定**：预警必须是**收缩圈**而不是闪烁色块 —— `rr = r * (0.35 + 0.65 * (t / telegraph))`，即从满半径一路收缩到 **35%**；外圈填充 alpha 0.20 + 描边 alpha 0.9、线宽 3，并叠一个随 `k` 变大的光晕。爆炸瞬间变成白色实心圆 + 强光晕。
**颜色约定**：敌方封锁是**粉红 `#f06595`**、己方天基炮是**金色**（`z.color`）—— 同一套视觉语言，两种归属。

**封锁伤害速查**（`enemyDamage(w) × 1.6`）：

| w | 1 | 10 | 20 | 30 | 45 |
|---|---|---|---|---|---|
| 封锁伤害 | 6.71 | 19.44 | 39.44 | 65.60 | 116.39 |

> ⚠️ `ZONE.max = 8` 只在 `spawnZones()` 里检查；**天基炮的落点是直接 `push`，不检查上限**。所以在壁垒者正在放圈时连打两发 Lv7 天基炮，场上可能出现 >8 个圈（见 16. 不一致）。

**负面强件**（Brotato 签名设计，本池已含）：命悬一线（伤害 +60% / 最大生命 −30%）、过载电容（伤害 +45% / 攻速 −15%）、装甲熔炉（减伤 +12% / 移速 −30）、战争机器（伤害 +35% + 攻速 +25% / 移速 −20）。代价必须落在"能不能做某件事"上，不落在封底为 0 的软肋上。

**武器吃不同属性**（`config.js: WEAPON_CLASS` + `game.js: weaponDamage()`）：`orbit/boomerang → melee`、`shot/flak/laser → ranged`、`nova/chain/orbital → elem` —— 所以"投哪项属性"取决于你拿了哪类武器（Brotato `scaling_stats` 的简化版）。

**机制层（阶段 A3）—— 商品能带来"新玩法"，不只是属性**：

属性组合能把商品做**多**，但只有机制能让商品做**有意思**。做法是 **机制 = 数据 + 钩子**：

| 项 | 说明 |
|---|---|
| 商品侧 | 商品带 `mech: '<id>'`；买下时把 handler 注册进 `player.mechs[id]`（**层数可叠加**，层数进倍率） |
| 游戏侧 | `MECH_REGISTRY`（`game.js`）+ `fireMechs(hook, ...)`；**只在固定事件点调用**：`onKill` / `onCrit` / `onDamaged` / `onWaveStart` / 商店价格 / 每帧被动 |
| 为什么 | 加一个新机制 = 一个 handler + 一行商品数据。**不许在十几个地方插代码**（本轮之前吃过亏：武器冷却散落 7 处） |
| 不污染面板 | 机制**不写进 `stats`**，所以 HUD 数值面板只显示真正的属性 |

现有 7 个机制：

| id | 名字 | 钩子 | 效果 |
|---|---|---|---|
| `chainkill` | 连锁反应 | onKill | 击杀时 70 半径爆炸（伤害随波次成长，`mechBlast` 带深度护栏防递归） |
| `critnova` | 暴击新星 | onCrit | 暴击时在目标处炸开，伤害 = 暴击伤害 ×30% |
| `vendetta` | 反击电容 | onDamaged | 受伤后 4 秒内伤害 +30% |
| `wavegift` | 波次补给 | onWaveStart | 每波开始回 12 生命 + 8 信用点 |
| `bargain` | 商人牌 | 价格 | 本局商店价格 −12%（可叠 2 层，`max: 2`） |
| `rage` | 背水一战 | 被动 | 生命 < 35% 时攻速 +25% |
| `standfast` | 锚定射击 | 被动 | 静止 0.8 秒后伤害 +30%，移动即重置 |

**验证（必须做，否则机制等于没做）**：`snapshot()` 暴露 `mechs`（当前机制列表）与 `mechBlasts`（机制爆炸次数）。实测：给满 7 个机制跑 150 秒 → **3,179 次爆炸**、0 error。
**平衡 A/B（180 秒 ×3 局）**：只带 `chainkill` vs 不带 —— 击杀 1570 → 1689（**+7.6%**）、10 秒均 DPS 5764 → 6745（**+17%**），爆炸 1,652 次。量级合理（T3、130 点）。


**单入口收敛**（阶段 A2 顺带做的）：`weaponDamage()` / `weaponCooldown()` / `effectiveRange()` —— 原来 `def.cd(lv) * player.cdMul` 散落 **7 处**、射程索敌散落 **5 处**，加一项属性要改十几处是必错的。


**价格公式**（`game.js: shopPrice()` → `config.js: shopPriceOf()`）—— **0.6.0 阶段 A 已改，旧 `SHOP_INFLATE` 模型作废**：

```
beat   = floor((G.wave - 1) / RUN.wavePerBeat)          // 小节序号，0 起，一局 9 小节
price  = max(1, round(base * (1 + SHOP_PRICE.pct * beat) + SHOP_PRICE.flat * beat))
         SHOP_PRICE = { flat: 3, pct: 0.15 }
```
- **为什么改**：旧模型 `base × (1 + 本局买过次数 × 0.60)` 每买一次全场 +60% —— 第二次购买价格就翻倍，于是"一局买 8 件以上"在数学上不可能；一局 12 次进店里 8 次是"什么都买不起"，那不是决策。
- 新模型随**小节**涨、与"买过几次"无关：比例项让贵货涨得更多，**平价项让便宜货后期更不划算**（形状抄 Brotato 的 `floor((基础价 + 波数 + 基础价×0.1×波数))`）。
- 价格只取决于小节，所以"现在买还是等下一小节买"是可算的。

### 9.5 局外存档与结算

来源：`game.js: META_KEY / META_DEFAULT / metaReward() / gameOver()`

**存档键**：`localStorage['starfall.meta.v1']`

| 字段 | 含义 |
|---|---|
| `v` | 存档版本号（当前 1） |
| `credits` | 局外信用点余额 |
| `runs` | 累计局数 |
| `kills` | 累计击毁 |
| `bestTime` | 最长存活（秒） |
| `bestWave` | 最远波次 |
| `playTime` | 总时长（秒） |
| `up` | `{ 强化 id: 等级 }` |

**结算公式**（`metaReward(run)`）：
```
reward = Math.round(run.t / 12 + run.wave * 2 + run.kills / 120)
```
（`run.t` 为秒）

| 示例 | 存活 | 波次 | 击毁 | 结算 |
|---|---|---|---|---|
| 早期阵亡 | 300 s | 15 | 400 | **58** |
| 典型一局 | 600 s | 30 | 1,500 | **123** |
| 长局 | 840 s | 44 | 3,000 | **183** |

结算时同时更新 `runs++`、`kills +=`、`playTime += t`、`bestTime / bestWave = max(...)`。最高纪录另存 `starfall.best.v1`（`{ t, kills, level, wave }`），只在 `cur.t > best.t`（同秒时比击毁）时刷新。

**面板文案**："本局结算 +{reward} 局外信用点（共 {总额}）· 局内剩余信用点 {N}"。

| id | 名称 | 图标 | 上限 | 价格公式 | 价格逐级 | 效果公式 | 满级累计 | 满级总花费 |
|---|---|---|---|---|---|---|---|---|
| `mhp` | 强化骨架 | 🛡️ | 5 | `60 + lv*60` | 60 / 120 / 180 / 240 / 300 | `b.hp += 5 * lv` | **+25 生命** | 900 |
| `mdmg` | 火控校准 | 🔥 | 5 | `80 + lv*80` | 80 / 160 / 240 / 320 / 400 | `b.dmgMul += 0.015 * lv` | **+7.5% 伤害** | 1,200 |
| `mcd` | 散热回路 | ⏱️ | 4 | `90 + lv*90` | 90 / 180 / 270 / 360 | `b.cdMul *= 0.99^lv` | **×0.9606（−3.94%）** | 900 |
| `mpick` | 磁力线圈 | 🧲 | 3 | `70 + lv*70` | 70 / 140 / 210 | `b.pick += 8 * lv` | **+24 拾取范围** | 420 |
| `mcred` | 回收协议 | 💠 | 3 | `100 + lv*100` | 100 / 200 / 300 | `b.credits += 15 * lv` | **开局 +45 信用点** | 600 |

**全部满级合计**：`{ hp: 25, dmgMul: 0.075, cdMul: 0.9606, pick: 24, credits: 45 }`，**总花费 4,020 局外信用点**。
按每局 58~183 点估算，全满级需要 **约 22–70 局**。

**应用时机**：只在 `reset()`（开场/重开）时通过 `metaBonus()` 一次性叠到玩家身上：
```
hp    = 机体 hp + mb.hp
pickupRange = 机体 pick + mb.pick
dmgMul = 机体 dmgMul + mb.dmgMul        // 加法
cdMul  = 机体 cdMul  * mb.cdMul         // 乘法
credits = mb.credits
```
**注意**：`bulwark` 的 `dmgMul = 1.15` 覆盖了基准的 1.3，所以永久强化的 +7.5% 是加在 1.15 之上（→ 1.225），不是 1.3 之上。

**研发终端面板**：显示累计局数 / 击毁 / 最长存活 / 最远波次 / 总时长；点击卡片购买（`meta.credits >= u.cost(lv)` 才生效并 `saveMeta()`）；满级卡片标记 `.on`（蓝框），买不起压暗 `.off`。

### 10.4 事件调度

| 事件 | 触发 | 内容 |
|---|---|---|
| 陨级单位（Boss） | `G.wave % 5 === 0`（每 5 波） | `spawnBoss()`，型号按 25/20/15/10 的优先级选（见 7.3） |
| 精英波 | `G.wave % 3 === 0` **且不是 5 的倍数** | `spawnEnemy(true)` × `3 + floor(max(0, w-12)/12)` 只；波次横幅下多一行"精英波"（20px 金字） |
| **优先级** | `if (wave % 5 === 0) … else if (wave % 3 === 0) …` | **互斥**：w15 / w30 / w45 等 15 的倍数**只出 Boss，不出精英波** |
| 事件预告 | 波末最后 **3 秒**（`WAVE_LEN - waveTimer <= 3`）且 `!eventWarned` | 下一波是 5 的倍数 → "⚠ 陨级单位 3 秒后抵达"；否则是 3 的倍数 → "⚠ 精英波 3 秒后抵达"。都伴随音效与闪光 |
| HUD 预告 | 常驻 | `#clockNext` 显示"下一波 [陨级 · / 精英 · ]{N}s"，事件波时转琥珀色 `.warn` |

### 10.5 局内进程结构：段 / 战斗小节 / 局内事件（0.6.0 阶段 0）

> ⚠️ 这一层是**叠加在 10.1–10.4 之上的分组**，`G.wave` 的语义与推进**完全没有改**。
> 原因：`ENEMY_SCALE(w)` / `SPAWN.rate(w)` / `ENEMY_ABILITY`（12/18/20/28/30 波解锁）/ Boss（每 5 波）/
> 精英化（w<4）**全部是波次 w 的函数** —— 把波次总数砍掉一截，整条难度曲线会当场失效
> （`ENEMY_SCALE` 的指数段从 w>25 才开始）。所以"小节 / 段 / 事件"只做分组，不替换波次系统。

常量在 `config.js: RUN` 与 `config.js: EVENTS`。

| 层级 | 定义 | 实现 |
|---|---|---|
| **一波** | `WAVE_LEN = 20` 秒（未改） | `G.waveTimer` / `G.wave` |
| **战斗小节** | `RUN.wavePerBeat = 4` 波 ≈ 80 秒（玩家感知的"一波"） | `G.beatWavesLeft` 倒计数，归零即小节结束 |
| **段** | `RUN.beatsPerStage = 3` 个小节 + **1 个局内事件** | `G.beatsLeft` 倒计数 |
| **一局** | `RUN.stages = 3` 段 | `G.stage` |

**相位机**（`G.phase`，唯一权威）：

```
beat ──小节结束──> smallShop ──关店──> beat
  └──本段最后一个小节──> event ──成败──> bigShop ──关店──> beat（下一段）
                                            └──已是最后一段──> gameOver() = 通关
```

- **小铺**（每小节之间）：从现有 6 件商品里随机抽 `RUN.smallShopItems = 3` 件
- **大铺**（每个事件之后）：6 件全上（分类商品池是阶段 1 的事）
- **升级面板优先**：`openShop()` 若发现 `pendingLevels > 0 || currentOptions`，把商店记进 `pendingShop` 排队，等升级弹完由 `flushPendingPanel()` 放出
- **自愈**：`updateRun()` 发现 `phase` 是商店态却没开店，会补开一次 —— 否则进程停在商店态没人推进，**一局直接卡死**（实测过：卡在 25 分钟原地空转）

**局内事件**（`EVENTS`，阶段 0 只做三种**零新系统**的，全部复用现有敌人与 Boss）：

| 事件 | 机制 | 成败判据 |
|---|---|---|
| **猎杀** | `spawnBoss(RUN…hpWaveAhead=10)`：目标血量按"当前波次 +10"算 | 22 秒内击毁 = 成功；超时 = 目标脱离 = 失败 |
| **据点固守** | 在玩家外 `offset=340` 处投放 `r=200` 的信标圈 | 圈内累计满 26 秒 = 成功；总时长超 `26 × 1.5 = 39` 秒 = 失败 |
| **波潮** | 刷怪速率 ×2.1，持续 35 秒 | **唯一的失败就是死** —— 故意留一种"没有借口、就是顶住"的事件，否则每个事件都在考同一件事 |

**奖励**：`RUN.reward = { win: 90, lose: 25 }` —— **占位数值**。A7 的"奖励档位"是阶段 4 的事，
阶段 0 只证明"成功和失败拿到的东西确实不一样"。

**事件期间**：`updateEvent()` 照常按当前波次速率刷怪（否则事件里没有压力），但 **`G.wave` 不再推进**
（`updateRun()` 直接转 `updateEvent()`）—— 所以那时 `#clockNext` 显示事件名而不是（冻结的）波次倒计时。

### 10.6 阶段 0 的实测与已知取舍（2026-09-28）

`__game.sim(1500, {bot:true})` × 6 局，调参前 → 调参后：

| 指标 | 初版 | 调参后 | 历史基线 |
|---|---|---|---|
| 单局时长 | **10.2 分钟** | **12.9 / 13.0 / 13.0 / 13.1 / 13.6**（6 局中 1 局 7.4 分钟早死） | 中位 13.3 |
| 波数 | 28 | 37 | 44 |
| 事件失败 | **0 / 12** | 2 / 18（猎杀超时） | — |
| 死亡 | 0 / 6 | 2 / 6 | 早死 ≤1 / 6 |

**调参前的问题**（都是实测出来的，不是推测）：猎杀时限 40 秒而机器人 **5.2 秒**就打死了
（8 倍余量 = 事件必然成功 = 等于没有事件）；据点硬上限 62 秒同样从没失败过。
→ 猎杀时限 40→22 且目标血量按 `w+10` 取；据点 `grace` 2.4→1.5；`wavePerBeat` 3→4。

**已知取舍（阶段 0 明确接受）**：

| 项 | 说明 |
|---|---|
| **波数 44 → 37** | 一局的战斗时长被事件与商店挤短了，`ENEMY_SCALE` 的后期段（w>25）拉不满。调 `RUN.wavePerBeat`（或 `WAVE_LEN`）就能补回来，**难度重算是阶段 4 的事** |
| **猎杀的失败率被低估** | 机器人**不追目标**（追一个 Boss 等于送死，它的武器射程 620、Boss 会主动贴上来）。所以实测的"猎杀超时"是机器人被动造成的，真人会主动去打 —— 真人的成功率应高于 2/3 |
| **波潮没有失败条件** | 故意的，见 10.5 |

| 自动降级判据 | 累计 **2 秒**窗口，平均帧时间 > **0.024 s（24ms ≈ 42fps）** → 降一档并飘字提示（"帧率不足 · 已关闭辉光" / "帧率不足 · 已切到最低画质"） |
| 只降不升 | 从 `high → mid → low`，不会自动升回来（避免来回抖） |
| 玩家手动优先 | 暂停面板里选过画质后 `fxUserSet = true`，**自动降级不再干预** |
| 持久化 | `localStorage['starfall.fx.v1']` |
| 手动入口 | 暂停面板的「画质」三连按钮（高/中/低，`.chip.q`，选中项 `.on` 高亮） |
| 单独开关 | 控制台里 `__game.fx.bloom = false` 可实时改（见第 14 节） |

### 12.5 预警的可读性约定

| 机制 | 约定 | 实现 |
|---|---|---|
| 狙击机预警线 | **线宽由细到粗 + 亮度由暗到亮**地"充满"，不是忽明忽暗的光束 | `lineWidth = 2 + 30k`；alpha `0.18 + 0.35k`；叠白线 `1 + 2k`；枪口充能环 `r + 4 + 4(1-k)` |

### 13.2 帧率无关阻尼

来源：`game.js: frameDrag()`

```
const frameDrag = (base, dt) => Math.pow(base, dt * 60);   // Demo 的系数都是 60fps 口径
```

| 用途 | 系数 |
|---|---|
| 数据残片速度 | `ORB_DRAG = 0.90` |
| 掉落物速度 | `0.92` |
| 敌人受击击退（`e.kx/ky`） | `0.86` |
| 粒子速度 | `0.94` |
| 震屏 | `0.86` |
| 全屏闪光 | `0.85` |

同理，镜头缓动用 `f = 1 - exp(-lag*dt)`，速度靠拢用 `min(1, k*dt)`，转向用 `maxTurn = TURN_ACCEL*…*dt` —— **一律乘 dt，不写"每帧固定量"**。

### 13.3 对象上限（全部有硬顶）

| 容器 | 上限常量 | 值 | 超限行为 |
|---|---|---|---|
| 敌人 | `MAX_ENEMY` | **260** | `spawnEnemy()` 直接 `return null` |
| 敌方弹幕 | `MAX_ENEMY_BULLET` (+`MAX_ENEMY_BULLET_RESERVE`) | **260**（精英/Boss 可到 340） | `fireBullet()` 直接丢弃（按 `src` 分配保留额度） |
| **友方弹体** | `MAX_ALLY_BULLET` | **600** | `fireAllyBullet()` 直接丢弃，并累计 `G.allyBulletDropped`（**不是静默**） |
| 数据残片 | `ORB_MAX` | **220** | **合并而非删除**：按距玩家距离降序排序，把超出部分的 `val` **并入第 220 颗**，再把长度截到 220 |
| 粒子 | `MAX_PART` | **700** | `burst()` 只补到剩余空间 |
| 飘字 | `MAX_TEXT` | **70** | `addText()` 直接 `return` |
| 区域封锁圈 | `ZONE.max` | **8** | `spawnZones()` 提前 `return`（⚠️ 天基炮不走这里，见 8.6） |
| 实光束 | `LASER.maxBeams` | **6** | 超出不上屏（纯视觉） |
| 同时预瞄狙击机 | `LASER.maxAim` | **3** | 保证预警可读完 |

**残片合并的实现与理由**（源码注释原文）："删掉等于静默销毁经验（表现就是'等级涨得莫名慢'，玩家查不出原因）"。配套地，残片的**视觉尺寸随价值缓慢增长**：`grow = min(1.9, 1 + log2(1 + val/2.5) * 0.22)`，光晕半径 `13 × grow`。

**友方弹体上限的理由（与敌方上限目的不同，别混用）**：敌方那个 260 是**可读性**旋钮；`MAX_ALLY_BULLET = 600` 是**性能护栏** —— 唯一的目的是挡住弹量失控（把武器扩到 20+ 把、开放 6 格且可重复之后，"多把高射速武器"能在开阔地带堆积），**正常构筑不该碰到它**。它不是平衡旋钮。

三个发射点（追踪弹族 / 近防霰弹 / 回旋切割器）曾经各自 `G.bullets.push`，与敌方弹幕当年是同一个坑（"改一处只生效一处"），现已全部收敛到单一入口 `fireAllyBullet()`。

**实测（2026-09，`__game.sim` + 浏览器实跑）**：

| 场景 | 友方弹体峰值 | 被上限丢弃 |
|---|---|---|
| 真实对局 ×3（11 把武器全 Lv7、43/42/41 波、13.4–14.3 分钟） | **255 / 260 / 257** | **0** |
| 6 把混合构筑（nano/flak/dart/boomerang/saw/laser）120 秒 | 134 | 0 |
| 病态：6 把重复满级纳米虫群（当前**造不出来**，武器唯一） | 319 | 0 |
| 病态 + `cdMul 0.5`（射速翻倍）180 秒 | 600（咬住） | 2832 |

> ⚠️ **P1（6 格 + 可重复）上线后必须复测**：届时"6 把同名武器"会成为合法构筑，峰值可能真的顶到 600。判据就是看 `allyBulletDropped` —— 它一旦在正常对局里不为 0，说明这个值定低了（或构筑真的失控）。这也是它必须**可观测**而不是静默丢弃的原因。

### 13.4 删除策略

| 容器 | 删除方式 |
|---|---|
| `texts` / `parts` / `bolts` / `rings` / `beams` | `swapRemove(arr, i)` —— **O(1) 且不搬移元素**（原 `splice` 在几百个对象同时过期时是 O(n²)，一颗战术弹就能造出数千粒子） |
| `bullets` / `enemyBullets` / `zones` / `pickups` / `orbs` / `enemies` | 倒序遍历 + `splice(i, 1)`（顺序无关但未改用 swapRemove —— 与不变式 #11 的字面表述有出入，见 16） |

### 13.5 视口剔除与弹体回收

| 项 | 值 |
|---|---|
| 渲染剔除 | `cull(x, y, m)`：屏幕外含 `m` px 边距的对象不提交绘制（炸弹/精英波会打死屏幕外的敌人并生成粒子，不剔除就是白烧 fill-rate） |
| 弹体回收 | `BULLET_CULL_MARGIN = 420`，**必须 ≥ 最长射程 − 视口半高**（780 − 360 = 420），否则上下方向飞不到面板上写的射程（射程是圆、视口是矩形） |
| 契约 | 不变式 #7："**越界回收一律按「视口外一段距离」判断，禁止再用 `W` / `H` 当世界边界**" —— 血的教训：改大世界时漏改子弹回收，子弹一生成就被删，玩家一整局打不出伤害 |

| 帧时间 | 420 敌人 + 120 敌方弹幕、后处理全开、rAF 采样 90 帧 | 门槛：**p50 < 10ms**；实测 p50 4.1–6.4ms |

**`sim()` 与真机的差异（源码文档明确警告）**：真机 `loop()` 在顿帧时会把 `dt` 乘 0.2（`hitStop`），而 `sim()` 以固定步长直接调 `update()`，**不套用这个缩放** → 真人反应时间比模拟里更宽裕，难度略低于模拟结论。另：`loop()` 把 `dt` 上限夹在 **0.05 秒**（`dt = Math.min(dt, 0.05)`）。

### 14.2 方法

| 成员 | 签名 | 说明 |
|---|---|---|
| `restart()` | `() => void` | 重开一局（`reset()`）；不会弹机体面板 |
| `sim(seconds, opts)` | `(number, { bot?, pick?, step?, shop? }) => snapshot` | **不渲染地推进模拟**。默认 `{ bot: botOn, pick: 'smart', step: 1/60 }`；步数上限 `60*60*60`。遇到 `G.paused` 会自动把升级面板选掉（`pick: 'random' \| 'first' \| 'smart'`）；**遇到补给终端会自动买一件（买得起的最便宜的）再关店**（`shop: false` 可关掉购买，只关店）；`G.over` 时提前退出 |

| `togglePause(force?, reason?)` | `(boolean?, string?) => void` | 手动暂停开关（`reason = 'blur'` 时焦点恢复会自动解除） |

| `killSelf()` | `() => void` | 立刻结束本局（`damagePlayer(1e9)`）—— 验证结算面板与纪录。⚠️ 无敌帧内或相位护盾会挡住，需要等 0.7 秒后重试 |

| `setZoom(z)` | `(number) => void` | 设目标镜头高度（夹在 0.7–1.6）并写 `localStorage` |

| 字段 | 含义 |
|---|---|

| `mk` | 型号名（`mkName(level)`） |
| `kills` | 累计击毁 |
| `hp` / `maxHp` | 当前 / 最大生命（`hp` 取整） |
| `dps` | **最近 1 秒**造成的伤害（`G.dmgSamples` 最后一格） |

| `orbs` | 场上残片数量（`G.orbs.length`） |

**批量测一局的标准模板**（来自 `reference/架构.md`）：

```js
for (let r = 0; r < 5; r++) {
  __game.restart(); __game.bot(true);
  while (!__game.G.over && __game.G.t < 1000) __game.sim(30, { bot: true, step: 1/40 });
  console.log(Math.round(__game.G.t / 60) + ' 分钟');
}
```

**`smartPick` 策略评分**（`sim` 的默认选卡策略）：

| 卡类型 | 分数 |
|---|---|
| `module`（超频模组） | 120 |
| `newWeapon`（武器 < 5 把时 / ≥5 把时） | 110 / 40 |
| `weaponUp` | 90 |
| `stat`（"落后"时：`maxHp < 260 \|\| dr < 0.2` 且 `level > 12` 且属于 `DEF_STATS`） | 95 |
| `stat`（其余） | 60 |
| 其它 | 5 |
| 随机抖动 | `+ Math.random() * 20` |

`DEF_STATS = { hp, hpPct, armor, heal, vamp }`。

## 15. 已知局限与待办

来源：`reference/更新计划.md`（待决策清单、验收门槛）、`reference/架构.md`（第 9 节待办、验证记录里的保留项）、源码注释中的自述限制。**源码里没有任何 `TODO` / `FIXME` 注释**（已 grep 确认），所有"待办"都在文档里。

### 15.1 设计上明确接受的局限

| 项 | 说明 | 出处 |
|---|---|---|
| **天基炮会打空** | 落点只按"目标朝玩家直线移动"前置，**突袭机（会冲刺）与狙击机（不贴身）都不吃**。设计意图就是"需要用减速/聚怪配合兑现"，不是 bug | `config.js` 注释、`game.js` 注释 |
| **保底只保证"有新武器"，不保证"有满级武器"** | 11 局批次里仍有 2 局早死（4.2 / 6.0 分钟，等级 24–25、8 把武器全是 Lv1–4），归因于抽卡运气差 | `reference/架构.md` 验证记录 |
| **拿不满全部内容** | 池子 127 次选择、一局只能拿到约 62 次 → 后期必须挑先练哪把 | `bench/weapons-check.mjs` 输出 |

| **一局波数被压到 37（原 44）** | 0.6.0 阶段 0 引入「段 / 战斗小节 / 事件」后，战斗时长被事件与商店挤短，`ENEMY_SCALE` 的后期段（w>25）拉不满。调 `RUN.wavePerBeat`（或 `WAVE_LEN`）即可补回 —— **难度重算是阶段 4 的事** | 见 10.6 |
| **加法混合的峰值饱和** | `lighter` 会让"发光 + 实体 + 核心"的东西峰值都顶到 250–255，所以**弹幕之间靠色相与形状区分，不靠亮度**；亮度分带只对单层绘制的东西（单位、碎片）有效 | `reference/架构.md` 5.2 |

| **换引擎的触发条件** | 单帧实体数要上到 2000+，或需要真正的着色器效果（法线/扭曲/多尺度 bloom）时才值得换 | `架构.md` 待办 |
| **镜头高度是玩家自选的难度杠杆** | 拉高镜头会让屏幕上同时出现更多单位；如果要收紧，可以按 `viewW()/W` 反向缩放刷怪率（当前未做） | `架构.md` 待办 |

### 16.4 值得注意但**不算**不一致的口径问题

| 项 | 说明 |
|---|---|
| `META_UPGRADES.desc(lv)` 显示的是"买完这一级之后的**累计**效果"，不是"这一级加多少" | 例：强化骨架在 `lv = 4` 时显示"最大生命 **+25**"，但 4→5 这一级的增量只有 **+5**（`b.hp += 5 * lv` 是累计式）。文案本身自洽，但容易被读成增量 |
| 卡面 `desc(lv)` 里的伤害是**面板值**，不是实战值 | 实战要再乘 `player.dmgMul`（开局 1.3）。同理冷却要乘 `cdMul`（0.9） |
| 敌人 "精英化" 与 "精英波" 是两套东西 | 前者是每次刷怪 5.9%–26% 的概率，后者是每 3 波的强制事件。**只有后者付信用点** |
